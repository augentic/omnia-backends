# omnia-sandbox

[![crates.io](https://img.shields.io/crates/v/omnia-sandbox.svg)](https://crates.io/crates/omnia-sandbox)
[![docs.rs](https://docs.rs/omnia-sandbox/badge.svg)](https://docs.rs/omnia-sandbox)

A host process in the model's trust domain, sandboxed. A model backend that runs a program on the host — `omnia-cursor`'s `cursor-sdk-bridge`, and the shell, `node`, `npm` and `git` the agent runs through it — spawns it through this crate, so what the process reaches is the host's decision and never the model's: a working directory, an environment built from nothing, a process group of its own, a kernel boundary around its files and syscalls, and one way out to the network.

MSRV: Rust 1.99

## What a sandboxed process gets

- **A working directory**: the workspace the guest lent, created and canonicalised, or a private directory under the session's scratch when nothing was lent. The child enters the workspace's open directory handle before it executes, so it runs where the workspace resolved and never walks the path again.
- **An environment built from nothing**: `PATH`, `LANG`, `LC_*`, `TZ` and `TERM` from the host; `HOME` and `TMPDIR` set to a scratch directory of the process's own, removed when it exits; `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` (and their lowercase spellings) naming the process's egress proxy, with `NO_PROXY` excepting the host's own loopback; the variables the backend names as `inherit`; then the `env` of the process's grant, a value's leading `~/` spelling the operator's home. An `inherit` or a grant that names a variable the sandbox sets itself, one the backend `refused` (its own credential), one the dynamic loader reads (`LD_*`, `DYLD_*`), an option list a runtime reads at startup (`BUN_OPTIONS`, `NODE_OPTIONS`), or a `GIT_DIR` sibling is refused — the inherit at connect, the grant at prepare — and a grant that names an `inherit` is refused too, since those are the program's own settings read of the host; so the host's credentials and repository selection never reach a shell command the model runs, and nothing of a grant runs code inside the program. A grant may set `PATH`, which the process inherits as set, but the bare program `Session::command` is given resolves against the host's `PATH` as connecting read it, so no grant chooses the program the backend spawns.
- **A process group of its own**: the child is a session leader (`setsid`), so it has no controlling terminal and `/dev/tty` opens nothing. A kill reaches the whole group — the processes the child forks included — and is sent before the child is reaped, so the group id is still held and cannot have been reused.
- **Access by location**: a workspace at or beneath one of the backend's `shell_roots` runs with a shell (`Access::Shell`); any other workspace is read-only (`Access::Read`); a private directory is neither (`Access::Private`). The backend reads the decision through `Session::access`, or asks it of `Sandbox::access` before preparing a session, so a backend with nothing to run outside a shell prepares no session elsewhere.
- **A kernel boundary**: the platform's kernel holds the process to its workspace, its scratch, the system, and the `read` roots of its grant — Seatbelt on macOS, Landlock and seccomp on Linux, each below. `Sandbox::connect` probes the kernel once and refuses where neither runs; nothing turns the kernel boundary off.
- **What the grant grants**: a `Grant` is what one process needs beyond the sandbox's own — `egress`, `read`, `env` — prepared with it by `Sandbox::prepare` and held to the host there. A `read` root is spelled `~/<path>`: a directory beneath the operator's home, which `connect` read canonical, so a target adapter names a toolchain (`~/.rustup`, `~/.nvm/versions/node`) without knowing the machine. One that does not exist is logged at WARN and granted nothing, so a toolchain this machine lacks is no reason to refuse the turn; one spelled any other way, stepping through `.` or `..`, resolving outside the home (a symlink out) or to a file, or asked where the host has no home, fails the prepare. The stores the operator's credentials live in are no grant's to read, whatever the deployment: a root that overlaps `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.azure`, `~/.kube`, `~/.docker`, `~/.config/gh`, `~/.config/gcloud`, `~/.password-store`, or `~/Library/Keychains` — at it, beneath it, or above it, as spelled or as either resolves, so neither `~/.config` nor a link to `~/.ssh` is a way in — fails the prepare too, on a machine that lacks the store as on one that has it.
- **One way out**: an HTTP `CONNECT` proxy on the host's loopback, bound per session and living as long as its process, is what the proxy variables name. It admits a host on the grant's `egress` list — a name whole, `*.suffix` for a domain and every host under it, an IP literal as itself — and refuses the rest with `403`; an empty grant admits nothing. Every address is vetted before the tunnel opens, a listed name resolved once and each answer classed, a listed literal classed as written: the unspecified, loopback, link-local, multicast and broadcast ranges, the cloud metadata addresses (`169.254.169.254`, `fd00:ec2::254`, `100.100.100.200`), a v4 address carried in v6 (mapped or v4-compatible) classed as the v4 address it carries, and the host's own interface addresses are refused, so neither a public name that resolves to the host nor a literal that spells it is a way back in. A loopback literal is the one exception, connected as written: a mirror on the host's loopback is a legitimate host, and the process reaches loopback on its own in any case. A private range is not refused: an internal registry is a legitimate host, and the grant lists it. Anything but `CONNECT` is `405`. A refused `CONNECT` is logged at WARN with its host, which is how an operator learns what a client needed. When the session's process is gone the proxy stops serving, the tunnels it carried closed with it.

## Seatbelt (macOS)

The program runs under `/usr/bin/sandbox-exec` with a profile rendered per spawn from Codex's base policy: `(deny default)`, the system roots readable, the workspace and the scratch writable, each `read` root of the grant and the program readable, the ancestors of every granted path readable by metadata so a path resolves, those above the workspace listable too — a Bun program, `cursor-sdk-bridge` among them, reads every directory on the way to its working directory before it reads its environment, and runs with none where one is closed — every path passed as a `-D` parameter rather than spliced into the profile, and `.git` and `.emery` beneath a workspace denied after the allow, so the model's own commits cannot be rewritten through the workspace. `process-info` is closed to processes outside the sandbox, so `ps` shows the host nothing and the callback token in the host's arguments stays hidden; the devices are `/dev/null`, `/dev/zero`, `/dev/random`, `/dev/urandom`, `/dev/fd`, and what the base policy opens. The network is closed to loopback: `network-outbound` to `localhost:*` alone and `bind`/`inbound` on any local port, so the workspace's own tests can run a server on port 0 and the proxy is the one route out. Nothing inside resolves a name, since the resolver is a network client too.

## Landlock and seccomp (Linux)

Requires a kernel with Landlock ABI 4 (6.7 or later, Ubuntu 24.04's 6.8 among them) and Yama's `kernel.yama.ptrace_scope` at 1 or more; `Sandbox::connect` probes both by creating a ruleset — never by forking — and reading the sysctl, and refuses naming the kernel version or the sysctl. At connect the host also sets itself non-dumpable (`prctl(PR_SET_DUMPABLE, 0)`, as ssh-agent does), so its `/proc/<pid>/environ`, `cmdline` and `maps` turn root-owned and a process inside reads nothing of the process that holds the credential; the cost is that the host writes no core dump and admits no same-uid debugger.

Per spawn, built in the parent and applied in the child before it runs the program: a Landlock ruleset handling every filesystem right of ABI 4 under `CompatLevel::HardRequirement`, anything short of full enforcement failing the spawn — `/usr`, `/bin`, `/sbin`, `/lib`, `/lib64` and `/lib32` read and execute, `/etc`, `/proc`, `/sys` and `/run` read, each skipped where the distribution lacks it; the workspace and the scratch every right; the program read and execute; each `read` root of the grant read and execute, since a toolchain lives there and Landlock grants execute by path; `/dev/null`, `/dev/zero`, `/dev/random` and `/dev/urandom` with file rights alone — and two seccomp programs: a deny list answering `EPERM` — `socket` for `AF_PACKET`, for `AF_NETLINK` with any protocol but `NETLINK_ROUTE` (which `getifaddrs` reads), and for `AF_INET` and `AF_INET6` with any type but `SOCK_STREAM`, the type compared under its mask so `SOCK_NONBLOCK` and `SOCK_CLOEXEC` do not slip the rule; `clone` with `CLONE_NEWUSER`; `ioctl` with `TIOCSTI` or `TIOCLINUX`, compared on the low 32 bits as the kernel reads them; and outright `ptrace`, `process_vm_readv`, `process_vm_writev`, `kcmp`, `pidfd_getfd`, `open_by_handle_at`, `unshare`, `setns`, the mount family, `bpf`, `userfaultfd`, `perf_event_open`, `personality`, `io_uring_*`, the module, kexec and keyring calls, `reboot`, the clock and hostname setters, `swapon`, `swapoff`, `quotactl`, `acct`, and on x86-64 `ioperm`, `iopl` and `modify_ldt` — and a one-entry filter answering `ENOSYS` for `clone3`, which glibc issues for every thread and falls back from (to `clone`, which is filtered) on `ENOSYS` alone.

**The Linux posture.** Landlock ABI 4 fences TCP by port alone, with no address filter, so a ruleset admitting only the proxy's port would also refuse a connect to the workspace's own test server on an ephemeral loopback port — the loop `npm test` against a server on port 0 runs. The ruleset therefore handles no network right: the kernel admits every TCP connect and bind, and egress on Linux is cooperative — the proxy variables, which npm, git, curl and the bridge honour — while seccomp refuses datagram and raw sockets, so the system resolver's UDP path answers nothing (a host running `nss-resolve` still answers over resolved's unix socket) and a client must either honour the proxy or carry an address of its own. macOS keeps its kernel fence. `/proc` must be readable (the loader, libuv, V8 and `sysconf` read it) and Landlock cannot carve `/proc/<other pid>` out of it, so inside, `/proc/<pid>/environ`, `cmdline` and `maps` of other same-uid processes are readable — Yama closes `mem`, and the host's own are closed by the non-dumpable flag. Landlock cannot deny beneath a grant either, so `.git` and `.emery` beneath a workspace are reachable on Linux where Seatbelt denies them. ABI 4 does not govern `AF_UNIX`, so a command inside can connect to any host unix socket it can path to. Same-uid loopback services are reachable from inside on both platforms, since the test loop needs loopback open. A mount and pid namespace, where the host admits unprivileged user namespaces, closes the `/proc` and `.git` exposures and makes the TCP fence the kernel's; a seccomp user-notification supervisor over `connect` closes it where the user namespace is blocked. Neither is in this crate yet.

## Usage

Connect once, then prepare a session per process with its grant:

```rust,ignore
use omnia_sandbox::{Grant, Options, Sandbox};

let sandbox = Sandbox::connect(Options {
    shell_roots: vec![".emery/vcs".into()],
    inherit: &["CURSOR_SDK_BRIDGE_LOG"],
    refused: &["CURSOR_API_KEY"],
})
.await?;

let grant = Grant {
    egress: vec!["registry.npmjs.org".into()],
    read: vec!["~/.nvm/versions/node".into()],
    env: vec![("VOLTA_HOME".into(), "~/.volta".into())],
};
let session = sandbox.prepare(workspace, &grant).await?;
let state_root = session.scratch().to_owned();
let mut command = session.command("cursor-sdk-bridge")?;
command
    .arg("--state-root")
    .arg(state_root)
    .ready_prefix("cursor-sdk-bridge ready ");
let mut child = command.spawn()?;
let ready = child.ready().await;
```

`Session::command` returns a `Command` scoped to the session: the program resolved on the host's `PATH`, the working directory, environment and kernel boundary already set, with `arg`, `args`, `env` and `ready_prefix` the only knobs. A `Session` is a handle, a clone naming the same session, and `command` borrows it, so one session runs one supervised child or any number of one-shots in turn — a build's `cargo check`, then its `cargo test`, in one `HOME` with one cache — and its scratch and proxy live as long as any handle or any process a command ran. `Command::spawn` is the supervised `Child`: `exited` resolves with its `Exit`, `fail_on_exit` runs a future under the process's life, `stop` asks the process to go through a future of the caller's and kills it when the ask goes unanswered, and dropping the child kills it outright. The last twenty lines it wrote to stderr are kept and logged at DEBUG when it exits on its own or a caller asks; its stdout is drained to DEBUG. `Command::output` runs the command once instead, capturing its output under a bound — each stream kept to sixteen mebibytes, the rest drained — and sweeping what the process forked once it has exited, so a fork left holding the pipes neither delays the exit nor outlives it. `Session::read_roots` is the roots the grant was granted, `Session::access` what the working directory admits, and `Session::scratch` the process's `HOME`; the proxy's address reaches the process through its environment alone.

## Tests

`cargo nextest run -p omnia-sandbox` runs every row over `/bin/sh` under the platform's kernel boundary: [`tests/child.rs`](tests/child.rs) is the process lifecycle — a forked grandchild swept with its parent on exit and on drop, an exit published with its tail, `fail_on_exit`, `stop`, the one-shot `output` with its bound, its sweep of a fork and its cap, and `/dev/tty` opening nothing with `ps` read from outside — [`tests/session.rs`](tests/session.rs) is what the process inside sees — its working directory and access, its environment, the connect-time refusals, the grant's rows (an absent root skipped and logged, a root held to the home, the grant's variables set with `~/` expanded and the held names refused, no home for `~/`, a proxy per session), and the kernel boundary's rows: on macOS a write outside the workspace, the host's home, `.git` and `.emery` beneath the workspace, `git status` in a linked copy, `ps` and the `kern.procargs2` sysctl of an outside process, a server on port 0, and a read root one session was granted and another not; on Linux ai-jail's escape matrix one syscall a row through the [`tests/support/probe`](tests/support/probe) helper, `clone3` refused with a thread still created, a write outside the workspace, the host's home, a read root kept, the host's `/proc/<pid>`, and a server on port 0 — and [`tests/proxy.rs`](tests/proxy.rs) is the proxy: an unlisted host, a suffix, a listed name resolving to loopback, a tunnel to a loopback literal carrying bytes and closed with the session, a listed literal of each refused class, a plain `GET`, the proxy variables inside, and on macOS nothing resolving or connecting inside but through the tunnel. The vetting table is a unit test beside the classification in `src/proxy.rs`. A row granting a `~/` root points the test process's `HOME` at a directory of its own first, so the operator's home is never touched. [`tests/toolchain.rs`](tests/toolchain.rs) is a build's toolchain inside the kernel boundary, needing `node` and `npm` on `PATH` (one under `$HOME` is granted as a `~/` root): a Node server on port 0 fetched from inside, `node --test` with a worker thread, and `npm install` of a `file:` dependency landing `node_modules/` and `package-lock.json` in the workspace with npm's cache in the scratch `HOME`; its ignored row, `npm_registry_install`, installs a pinned `typescript` from `registry.npmjs.org` through the proxy and runs `tsc --noEmit`, run by hand with the network.
